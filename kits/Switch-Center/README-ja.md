# Switch コントロールセンター

## v0.4.0（2026-10-26）: 段階3（電源・ドライバー・記録のタブ）

- **電源:** 今の電源プランの、AC とバッテリーの両方に設定する（Windows の PowrProf の API）。
  - 電源ボタンを押したとき: 何もしない / スリープ / 休止状態 / シャットダウン / 画面を消す
  - 画面を消すまでの時間: 1〜30 分 / 消さない
  - 電池が少なくなったとき: 動作と、少ないとみなす残量（%）
  - Windows がバッテリーを認識しているかの表示。段階0では「認識していない」と出ていたので、そのときは電池が少ないときの動作は働かない。
  - スリープと休止状態は、まだ確かめていないので「（未確認）」と表示する。
- **ドライバー:** DSDT の Switch のデバイス（ACPI\SWOA0101〜0801）ごとに、次を一覧にする。I2C は3つ分。
  - 状態: 正常 / エラーのコード / デバイスが無い
  - 入っているドライバーの版
  - 動いているドライバーの版（記録の DriverVersion）
  - 「更新を確認」は、ドライバー用のリポジトリ（OTA）ができるまで押せない。設計は `..\Design-DriverRepo-OTA-ja.md`。
- **記録:** 困ったときの情報（デバイスの一覧、各ドライバーの記録、電源の情報）を表示する。「困ったときの情報を保存」で、デスクトップに ZIP として保存する。各スクリプトのログ（`C:\SwitchWOA-*.txt`）も入れる。
- **PC での確認:** 3つのタブを開いて、レイアウトを確かめた。
- **未確認:** Switch での動作。特に、電源の設定を普通のユーザーの権限で変えられるか。

## v0.2.1（2026-10-26）: 使用率とメモリ

- **Switch での v0.2.0:** 概要のタブは、表示も値も正しかった（1018 MHz、41 ℃、65 %、100 %、グラフ）。
  - ただし、USB-C が「不明」だった。バッテリーのドライバーは、状態が変わったときにしか USB-C の値を記録していなかったため。
- **追加したもの:** タイルを3段にして、「CPU の使用率」と「メモリ」を足した。
  - 詳しい状態に、コアごとの使用率を足した。
  - グラフに、使用率の線を足した（緑、0〜100%）。
  - 使用率は、Windows のコアごとの時間（NtQuerySystemInformation）から計算する。メモリは GlobalMemoryStatusEx で読む。
- **直したもの:**
  - アプリ: USB-C の状態がまだ記録されていないときは、ドライバーの起動時の値を使うようにした。
  - バッテリーのドライバー v5（1.0.0.5）: 起動時にも USB-C の状態を記録するようにした。これで、前回の起動のときの値が残らない。

## 段階2（v0.2.0、2026-10-26）: 大きな画面

- **開き方:**
  - 通知領域のメニューの一番上「コントロールセンターを開く」から開く。
  - アイコンをダブルクリックしても開く。
  - `SwitchCenter.exe --open` で起動すると、最初から画面を開く。
- **閉じたとき:** ×で閉じても、画面が隠れるだけ。アイコンは残る。アプリを止めるときは、メニューの「終了」を使う。
- **概要:**
  - CPU のクロック、SoC の温度、バッテリー残量、画面の明るさを、大きなタイルで並べる。SoC が 70 ℃ 以上のときは、温度の数字が赤くなる。
  - 詳しい状態として、次を表示する。
    - CPU の電圧、基板の温度、ファンの duty
    - 電源（AC・充電中など）、バッテリーの電圧
    - USB-C の状態
    - 温度による制限
  - 直近5分の SoC の温度（赤）と、CPU のクロック（青）のグラフ。グラフは、画面を閉じている間も2秒ごとに記録している。
- **パフォーマンス:** プロファイルを大きなボタンで選ぶ。選んだものが押された状態になり、今動いているものは太字になる。試験的なプロファイルは黄色で、選ぶと確認の画面が出る。
- **画面:** 明るさのスライダー（3〜100%）。指を離さなくても、動かすとすぐに明るさが変わる。画面の状態（オン、暗くしている、オフ）も表示する。
- **値の取り方:** バッテリーの値は、Windows 標準の API ではなく、ドライバーの記録を使う。標準の API は、この Switch では「バッテリー無し」と返すため。
- **PC での確認:** x64 版で画面を開き、概要のタブのレイアウトを確かめた。PC にはドライバーが無いので、値は「—」になる。
- **未確認:** Switch での表示。

## 段階1：通知領域のアイコン

設計は `..\Design-ControlCenter-ja.md`。段階1では、今の常駐アプリ `SwitchClock.exe` と同じことを、.NET 8 の ARM64 版で作り直した。大きな画面（概要・パフォーマンス・画面のタブ）は段階2で作る。

## 中身

| ファイル | 内容 |
|---|---|
| `SwitchCenter\` | アプリの本体。`SwitchCenter.exe` と、同梱の .NET 8（ARM64、自己完結型）。約 160 MB |
| `SwitchCenter.zip` | 上のフォルダーを ZIP にしたもの（約 59 MB）。Switch へ運ぶとき用 |

ソースは `..\SwitchCenter\src\`。

- `Devices.cs`: ドライバーとのやり取り（CPU、バックライト、記録の読み取り）
- `TrayApp.cs`: 通知領域のアイコンとメニュー
- `Program.cs`: 起動。同時に1つだけ動くようにする

## SwitchClock との違い

- **動き方:** x86 のエミュレーションではなく、ARM64 のネイティブで動く。
- **配り方:** 1つの exe ではなく、フォルダーで配る。1ファイルにまとめた exe は、起動のたびに中身を展開するので、約3秒かかっていたため。さらに ReadyToRun（事前コンパイル）で、起動を速くしている。
- **設定:** 前回のプロファイルは SwitchClock と同じ場所（`HKCU\Software\SwitchWOA\SwitchClock` の LastProfile）を使うので、そのまま引き継ぐ。
- **自動起動:** 「ログイン時に起動」をオンにすると、SwitchClock の自動起動は消す。2つが同時に起動するのを防ぐため。

メニューの中身（プロファイル、画面の明るさ、ログイン時に起動、終了）と、アイコンの色の意味は、SwitchClock と同じ。

## 手順

1. **SwitchClock を止める。** 動いていたら、メニューの「終了」で閉じる。
2. **コピーする。** `SwitchCenter.zip` を Switch にコピーして展開する。例: `C:\SwitchWOA\SwitchCenter\`。
3. **起動する。** `SwitchCenter.exe` をダブルクリックする。管理者として実行する必要はない。
4. **確かめる。**
   - 通知領域にアイコンが出て、今のクロックが表示されるか。
   - プロファイルと明るさを切り替えられるか。
   - 起動の速さ（アイコンが出るまでの時間）。
5. **（任意）自動起動にする。** 「ログイン時に起動」をオンにして再起動し、SwitchCenter だけが起動するかを見る。
