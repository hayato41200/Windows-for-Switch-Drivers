# SwitchGpu 0.18.0 実機テストキット

Nintendo Switch（Erista）の GM20B を Windows ARM64 で起動し、描画、割り込み、停止を確認するキットです。UEFI の GPU0（`ACPI\SWOA0F01`）が必要です。E3 の割り込み試験は **R447H 以降**で実行できます。

署名済みのキットを展開して `Install.cmd` を実行します。各 CMD は管理者権限を求めます。ファームウェアは自分で用意した linux-firmware の `nvidia/gm20b` 一式を、キット内の `firmware\nvidia\gm20b` または `C:\SwitchWOA\firmware\nvidia\gm20b` に置いてください。Resident と Cycle が ACR・PMU・FECS・GPCCS および GR の初期化データを取り込みます。取り込み済みならレジストリのコピーも使えます。

F4 の `DoubleBuffer` は既定で 0 です。`F4Off.cmd` と再起動で従来の単一バッファに戻ります。パネルの標準画面は1枚 3,686,400 バイトで、4.5 MiB の予約領域には2枚入らないため、2枚目を 4 GiB 未満の物理連続 WC メモリに確保します。TV は現在のラスタと同じサイズの WC バッファを追加します。1080p では1枚 8,294,400 バイトです。確保に失敗した出力は単一バッファで動作します。

DC-A／DC-B の Window A を選び、assembly バンクに開始アドレスを書き、GENERAL／WIN_A の UPDATE、ACT_REQ を順に発行します。ACT_REQ の解除と active バンクの開始アドレスを最大約50 ms確認します。タイムアウト時は両バッファを最新画像にそろえてフリップを打ち切り、走査が残り得るバッファは解放しません。通常終了では元の走査アドレスを確認して解放します。

UEFI のパネル先頭アドレスが既知の予約範囲外なら、そのバッファの GPU 用 MDL は作りません。ドライバーが確保した2枚目は GPU からアクセスでき、従来のバッファを GPU で安全に扱えない向きや回転・拡大縮小では CPU を使います。F4 と F3 は個別に切り替えられます。

`AutoTest.cmd` はインストールと Windows 再起動を行い、サインイン後に Resident → Irq → Submit → Copy → Blit → ResidentStatus → ResidentStop → Cycle を一度だけ実行します。表示ドライバーの導入と F3 の有効化は手動です。`AutoTestCancel.cmd` は予約と再起動を取り消し、`Remove.cmd` は GPU ドライバーを削除します。

G1 は `AutoResident=1` のときだけ有効です。`switchgpu\Parameters` の DWORD `IdlePowerOffMs` の既定値は 10000 で、0 に設定して再起動すると従来どおり常駐します。`F3On.cmd` は既存値を保持します。GPU 停止後に起動を要求できるのは、GPU に送られる Present です。回転や小さな更新など、表示側が CPU に直接回す処理は対象外です。起動中も CPU 描画を続けます。

自動再起動が2回連続で失敗すると、その Windows 起動中の自動起動を止めます。`ResidentStop.cmd` による手動停止後も自動復帰を止めます。`F3Status.cmd` の G1 行で停止・起動件数、直近の起動時間、失敗数を確認できます。低クロックの中間状態は設けていません。

F2/F3 の GPU VA は `0x20000000` と `0x21000000` から各16 MiBです。GR プールを `0x248000` バイトに拡張し、末尾に GPU の4 KiBページ用テーブル256 KiBと Tegra SMMU のテーブル8枚（計32 KiB）を置きます。マップと解除のたびに SMMU の PTC/TLB と GR PDB の TLB を無効化します。

`F2b bench` は各試験の所要時間と転送量を表示します。a は全画面20回を別々に投入、b は全画面20回を1回で投入、c は1080行を1回で投入して全画面1回分を転送します。WC の GPU 計測は a と同じ投入方法です。計測にはコマンド生成と完了待ちを含み、マップ・照合時間は除きます。一括コマンドは既存 GR arena の `0x0B0000` から64 KiBを使い、待ちは最大2秒を目安に打ち切ります。stage が0以外なら、1が準備・矩形照合、2〜4がGPU a/b/c、5がCPUキャッシュあり、6がGPU WC（割り当てを含む）、7がCPU WCです。

`F2b clock` は基板の 38.4 MHz 水晶と CAR の PLL 参照分周を使った公称値です。バイパス時は周波数を未確定として表示します。VDD_GPU は MAX77621 の VOUT コードから換算した設定値を表示します。TRIM は有効な測定窓が既にあり、カウントが安定していれば、その窓の測定値を表示します。クロックや電圧の設定は変更しません。

`F2c step` は周波数、CVB 電圧、M/N/PL、ロック・ランプのポーリング回数、TRIM のアイドル時の測定値、照合件数と帯域を記録します。CVB は Nouveau の非 NA、speedo ID 0 の表を使い、GPU speedo ヒューズの世代別換算のうち要求電圧が最も高い値を採用します。VOUT 読み返しが 1000 mV でないときや、参照クロックが 38.4 MHz と確認できないときは段をスキップします。ロックやコピーの失敗で打ち切り、PLL を無効化してバイパスへ戻します。DMA 停止やバイパスへの復帰を確認できなければ GPU をリセットします。

既定の常駐起動はバイパスです。必要なときだけ `HKLM\SYSTEM\CurrentControlSet\Services\switchgpu\Parameters\GpcKhz` に DWORD で 76800 kHz 刻みの表の値（最大 614400 kHz）を設定し、次回の常駐起動で適用できます。0 はバイパスです。設定結果は `F2cResidentClockResult` に記録します。Blit の終了後は設定値に関わらずバイパスで動きます。電圧は従来の常駐起動設定のままです。

F3 は試験用 switchdisplay 1.7.1 の `GpuPresent` と switchgpu の `AutoResident` を使います。表示ドライバーは同期の内部 IOCTL `0x22E01C` で MDL・ピッチ・最大64矩形を渡します。回転・拡大縮小は従来どおり CPU が処理します。コピーが完了しなければ GPU を緊急リセットし、DMA 停止を確認できた場合に CPU へ戻します。リセットと DMA 停止を確認できなければ、そのバッファを再利用せず再起動まで保持します。

F1 は既存の GR チャネルで B0B5 をサブチャネル4に割り当てます。GR arena 内の相対位置 `0x1DA000` にコマンドとセマフォ、`0x1E0000` と `0x1F0000` に入出力バッファを置きます。成功時は `F1 copy result 0x00000000` と `16/16` が出ます。完了を確認できなかった場合は `pending 1` を記録し、ResidentStop でリセットしてから再試行できます。

ログは `C:\SwitchWOA-Gpu.txt` に追記します。詳細が必要な場合は `VerboseOn.cmd` を実行し、次のデバイス起動後に試験してください。`VerboseOff.cmd` で次回起動から通常の記録に戻ります。`Gpu.ps1 -Mode Status -Detail` はレジストリに保存済みの詳細を表示します。

0.8.0 では E1〜E4 を実機で確認済みです。0.9.0 は旧試験モードを整理し、通常時のログ量を減らしました。参照コードの出典とライセンスは `NOTICE-GM20B-MMU.txt` に記載しています。

## H1: プロセスごとの GPU VA 空間（0.16.0）

Vulkan ドライバー（Mesa NVK）を switchgpu の上で動かすための最初の段階です。ユーザーモードのプロセスが、GPU のメモリーを確保し、CPU から読み書きし、GPU（CE2）でコピーできるようにしました。

- **VA 空間**: ファイルハンドル（ふつうは 1 プロセスに 1 つ）ごとに、GPU VA `0x40000000` から 32 MiB の空間を 1 つ割り当てます（同時に 4 つまで）。空間ごとに専用の GPU ページテーブル（4 KiB ページ、256 KiB）と、専用の IOVA 範囲（空間 s は `0x40000000 + s × 32 MiB`）および Tegra SMMU のページテーブルを持ちます。2 つのプロセスは同じ GPU VA の数字を使いますが、指す物理ページは別です。
- **切り替え**: 常駐 GR チャネルのページディレクトリーは 1 つなので、コピーのたびにその空間の PDE（GR の PDE 8 と SMMU の PDE）だけを書き、TLB を無効化してから CE2 を動かし、終わったら消します。ある空間を使っている間、ほかの空間の PDE は 1 つも存在しないので、GPU は IOVA を使っても他人のページに届きません。コピーの前に、使うページの GPU PTE と SMMU PTE を読み返して確かめます。
- **メモリー**: `MmAllocatePagesForMdlEx`（ライトコンバイン、ゼロ埋め）で確保し、呼び出したプロセスにライトコンバインでマップします。1 回の確保は 16 MiB まで、1 ハンドルで 32 個まで。確保のあとに 1 ページの空き（ガード）を置きます。ハンドルを閉じるかプロセスが終わると、マップを外してページを返します。
- **衝突しない範囲**: 表示の GPU Present（IOCTL `0x22E01C`）はウィンドウ 0/1（GPU VA `0x20000000`、PDE 4、IOVA `0x20000000`）を使い、GR arena は `0x18000000`（PDE 3）です。H1 は PDE 8 と IOVA `0x40000000`〜`0x48400000` だけを使います。コピーは表示と同じ `BlitGate` で順番に動きます。
- **IOCTL**（管理者のみ）: `0x22E020` 確保、`0x22E024` 解放、`0x22E028` コピー、`0x22E02C` 状態。確保・解放・状態は呼び出したプロセスの中で処理します。コピーは他の GPU の IOCTL と同じ順番待ちの列を通ります。
- **G1 との関係**: GPU が停止中（アイドルで電源オフ）のときにコピーを頼むと、ドライバーが GPU の起動を予約して「まだ準備できていない」を返します。試験ツールは最大 20 秒まで待ってやり直します。G1 が無効で GPU が常駐していない場合は、先に `Resident.cmd` を実行してください。
- **H1 で未対応のこと**: ユーザーが自分のコマンド（プッシュバッファー）を出すこと、プロセスごとのチャネル、フェンス（これらは H2）。ハンドルを別のプロセスに複製し、作ったプロセスより長く使う使い方には対応していません。コピーが止まらず GPU のリセットも確かめられなかった場合は、そのページを再起動まで返しません（`quarantined 1`）。

`Mem.cmd` のログは `C:\SwitchWOA-Gpu.txt` に追記されます。各プロセスの行は `W1:`・`W2:`・`W3:` で始まります。`isolation ok 1` は、その空間のページテーブル全体（128 MiB 分）を調べ、自分の確保以外の有効な PTE が 1 つもないことを表します。

## H2a: プロセスごとの GPU チャネル（0.17.0）

H1 の VA 空間を持つハンドルは、GPU チャネルを 1 本作れます（`0x22E030`、Op 1 で作成、2 で削除）。

- **チャネルの中身**: 専用のインスタンスブロック（RAMFC、ページディレクトリーの指定）、専用のページディレクトリー、ゴールデンイメージから作った専用の GR コンテキストとパッチページ、GPFIFO（512 エントリー）、カーネルが足すフェンス用のページ。チャネル番号は空間番号 + 1 です。カーネルの常駐チャネル（chid 0）と同じ GR ランリストに並び、ハードウェアが時間で切り替えます（FECS のコンテキスト切り替え）。
- **見える範囲**: チャネルのページディレクトリーには PDE 3（`0x18000000`）と PDE 8（`0x40000000`、H1 と同じユーザーの表）しかありません。PDE 3 には自分の GR コンテキスト、共有の GR グローバルバッファー、priv access map を **特権ページ** として置き、GPFIFO・フェンスのページ（`0x18200000` から）だけを通常のページとして置きます。ほかのプロセスのメモリー、カーネルの arena、ページテーブル、表示のバッファーはマップされていません。
- **提出とフェンス**: `0x22E034`（プッシュバッファーの GPU VA と長さ）。プッシュバッファーは自分の確保の中にある必要があります。カーネルは GPFIFO にその後ろへ「WFI 付きのホストセマフォ解放」を足し、フェンス番号を返します。`0x22E038` でフェンスを待ちます（呼び出したプロセスの中で待つので、ほかの IOCTL を止めません）。同時に出せるのは 64 回まで。
- **電源**: チャネルがある間は G1 のアイドル電源オフをしません。常駐の停止・リセットが起きると、チャネルは失われます（提出が `0xC00002B6` を返す）。そのときの後片付けはメモリーを返すだけです。
- **解放と TLB**: チャネルがある空間でメモリーを解放するときは、PTE を消し、L2 を flush し、そのチャネルのページディレクトリーの TLB を無効化してからページを返します。
- **切り分け用の設定**: コンテキストを特権ページにしたせいでコンテキスト切り替えが止まる場合に備えて、`switchgpu\Parameters` の DWORD `H2PrivPtes` を 0 にすると、特権ビットなしでマップします（隔離は弱くなるので、試験のときだけ使います）。次のチャネル作成から効きます。
- **H2a で未対応のこと**: ユーザーのプッシュバッファーが MMU fault を起こしたり止まったりしたときの回復（H2c）。いまはフェンスの待ちが 2 秒でタイムアウトし、チャネルの削除でも止められなければ GPU をリセットします（そのあとは `ResidentStop.cmd` → `Resident.cmd` が必要です）。

`Chan.cmd` の各プロセスの行は `C1:`・`C2:`・`C3:` で始まります。失敗したときは `registers:` の行に、チャネルの状態、エンジンの状態、PBDMA・FIFO・GR の割り込み、MMU fault の値が出ます。

## H2c: 障害からの回復（0.18.0）

GM20B では GR と CE2 が同じランリストを使うので、1 本のチャネルが MMU fault を起こしたり止まったりすると、ほかのチャネルも全部止まります。GR だけのリセットにはコンテキスト切り替えのファームウェアの読み込み直しが要るため、回復は **G1 と同じ GPU の再起動**（常駐の停止 → 起動）で行い、次のように後始末します。

- **犯人を決める**: MMU fault の記録にあるインスタンスのチャネル → GR に載っているチャネル（エンジンの状態）→ PBDMA に載っていて仕事が残っているチャネル → いちばん長く進んでいないチャネル、の順。犯人のチャネルは以後の提出と待ちに `0xC0000185`（FAULTED）を返します。プロセスはそのチャネルを消して作り直せます。
- **ほかのチャネル**: 新しいコンテキストで作り直し、終わっていなかった提出を GPFIFO に入れ直します（途中まで動いていた提出は、最初からもう一度動きます）。カーネルの常駐チャネルは空の状態から再開し、その間の表示は CPU で描きます。
- **きっかけ**: 提出・待ちのときに MMU fault を見つけたとき、待ちのときに仕事が残ったまま 3 秒進まないチャネルを見つけたとき、G1 のタイマーが「カーネルのコピーが打ち切られて GPU がリセットされた」状態を見つけたとき（以前は G1 を止めていました）。
- **回数の制限**: 1 分に 5 回まで。超えたら以前と同じく GPU は止まったままになります（`ResidentStop.cmd` → `Resident.cmd` でやり直せます）。DMA の停止を確かめられなかった場合（quarantined）も回復しません。
- **記録**: `switchgpu\Parameters` の `H2Recoveries`、`H2LastReason`（1 fault、2 hang、3 reset、4 G1）、`H2LastCulprit`、`H2LastMmuFault`、`H2LastFaultInst`、`H2LastRecoverUs`、`H2LastRebuilt` など。`Fault.cmd` が最後にまとめて表示します。

`Fault.cmd` の各プロセスの行は `F1:`（無実）・`F2:`（MMU fault）・`F3:`（ハング）で始まります。
