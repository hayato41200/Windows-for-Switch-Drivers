
## 変更内容 / What changed

**画面を消すと CPU が省電力になり、GPU で画面を描く機能（実験的）をコントロールセンターでオンにできるようになりました。**

- **CPU のクロック 1.0.0.4:**
  - 画面が消えている間は、CPU を一番低いクロック（614.4 MHz）に下げます。画面が点くと、選んでいたプロファイルに戻します。
  - レジストリ `switchcpu\Parameters\ScreenOffLowPower` を 0 にすると、この動きを止められます。
- **バッテリー 1.0.0.10:**
  - 電池の電流、消費電力、残り容量を 10 秒ごとに記録します（電力の測定に使います）。表示や動きは変わりません。
- **GPU 0.14.0（実験的、初めてリリースに入ります）:**
  - 初期状態ではオフで、何もしません。
  - 使うには、自分で用意した GPU のファームウェア（linux-firmware の `nvidia\gm20b`）が必要です。SwitchPatcher 0.6.1 か、コントロールセンターのファームウェアの取り込みで入れられます。NVIDIA のファイルは、このリリースには入っていません。
- **画面 1.10.1:**
  - GPU で描画するとき、ダブルバッファの 2 枚とも、GPU から書けるメモリを使うようにしました。これまでは 2 枚のうち 1 枚が UEFI の画面メモリで、GPU から書けなかったため、描画の半分ほどが CPU に回っていました。
  - GPU を使わないときの動きは 1.8.0 と同じです。
- **コントロールセンター 0.10.0:**
  - 「画面」タブに「GPU（実験的）」の欄を追加しました。「GPU で画面を描く」にチェックすると、ファームウェアを読み込んで GPU 描画とダブルバッファをオンにします。Windows を再起動すると切り替わります。
  - GPU が動いているか休んでいるか、GPU と CPU で描いた回数も表示します。
- UEFI は R448H のままです（変更なし）。

**実機で確認したこと:**
- バッテリー 1.0.0.10 と CPU のクロック 1.0.0.4 を入れて、起動と再起動ができること。
- 電池で 96.5 分（そのうち 92.7 分はスタンバイ）置いたとき、平均の消費電力が約 2.6 W だったこと（満充電から約 6 時間）。
- コントロールセンター 0.10.0 で GPU をオンにして再起動すると、GPU で描画できること。失敗 0、画面の切り替えの時間切れ 0。
- 画面 1.10.1 で、GPU から書けない描画が 0 回になったこと（1.8.0 では 1230 回）。
- 画面 1.10.1 と GPU 0.14.0 で、Windows の再起動ができること。

**まだ確認していないこと:**
- コントロールセンターの更新（OTA）でこのリリースを入れること。
- 画面が消えている間、CPU が実際に 614.4 MHz に下がっていること。
- コントロールセンターで GPU をオフに戻すこと。
- ドライバーの入れ替えが残っているときの再起動で、まれに止まること（以前からの問題）。

**今後実装する予定:**
- Wi-Fi の省電力（通信していないときのタイマーと省電力モード）と、無効にしたあと戻らない問題の修正。
- 再起動が止まる問題の調査。
- GPU: アプリの描画（Direct3D）を GPU で行う方法の調査。

**The CPU saves power while the screen is off, and GPU drawing (experimental) can be turned on in the control center.**
- CPU clock 1.0.0.4: while the screen is off the CPU runs at its lowest profile (614.4 MHz) and goes back to your profile when the screen comes on. Set `switchcpu\Parameters\ScreenOffLowPower` to 0 to turn this off.
- Battery 1.0.0.10: records the battery current, power and remaining capacity every 10 s (for power measurements). Nothing visible changes.
- GPU 0.14.0 (experimental, new in the release): off and idle by default. It needs your own GPU firmware (linux-firmware `nvidia\gm20b`), added with SwitchPatcher 0.6.1 or the control center's firmware import. No NVIDIA files are in this release.
- Display 1.10.1: with GPU drawing on, both buffers of the double buffer are GPU-writable driver memory. Before, one of them was UEFI's framebuffer, which the GPU cannot write, so about half the presents went to the CPU. Without the GPU it behaves like 1.8.0.
- Control center 0.10.0: the Display tab has a "GPU (experimental)" box. Turning it on reads the firmware and enables GPU drawing and double buffering from the next restart. It shows whether the GPU is running or resting and how many presents went to the GPU and to the CPU.
- UEFI stays R448H.
- Tested on hardware: battery 1.0.0.10 and CPU clock 1.0.0.4 install and boot, restart OK; 96.5 min on battery (92.7 min in standby) averaged about 2.6 W (about 6 h from full); GPU drawing turned on from control center 0.10.0 works after a restart (0 failures, 0 flip timeouts); with display 1.10.1 no present lacks a GPU destination (1230 with 1.8.0); Windows restarts with display 1.10.1 and GPU 0.14.0.
- Not tested: installing this release over the air; that the CPU really reaches 614.4 MHz with the screen off; turning GPU drawing off again; a rare hang when restarting with a pending driver replacement (known before).
- Planned: Wi-Fi power saving (timer and power-save mode when idle) and the Wi-Fi re-enable fix; the restart hang; GPU: researching app drawing (Direct3D) on the GPU.
